# Sounder

A native audio recorder and editor for macOS 14+ (Apple Silicon), built with AppKit and AVFoundation. Author: Dzmitry Sharko. The Xcode project structure and npm commands follow FalconCleaner; Developer ID team: `W37L5728Y6`, bundle ID: `enotix.Sounder`.

## Running and building

- `npm start` — terminates existing processes with the exact name `Sounder`, waits for them to exit, builds and launches the app, and verifies that exactly one process is running.
- `npm run build:app` — creates a Release build at `build/Release/Sounder.app`. Uses Developer ID signing when the certificate is available; otherwise, explicitly reports that local ad-hoc signing is being used.
- `npm run build:icons` — regenerates all ten macOS AppIcon sizes from the original artwork. See [icon artwork and generation prompt](Design/AppIcon/README.md).
- `npm test` — builds the app and runs audio engine and editing tests.
- `npm run release:local` — creates a signed DMG without notarization.
- `npm run release` — creates a signed and notarized DMG; the Keychain profile is set through `NOTARY_PROFILE` (default: `falcon-notary`).
- `npm run clean` — removes build artifacts.

## Usage

1. Click Record or press R. Allow microphone access when recording for the first time. Stop / Escape finalizes a separate WAV fragment. During recording, Space saves the take and returns to its start; Enter discards the current take and immediately records a fresh take from the same position on the same track. Each new recording starts at the playhead on the selected track. Record / R is also available during playback: existing tracks continue on the same engine while the new take captures only microphone input. Starting Record from stopped starts the backing mix at the selected cursor; recording can continue past the end of existing material. The metronome plays once on the backing output, and other tracks retain their playback meters.
2. Import / ⌘I imports audio; multiple selected files are placed sequentially. A nonmodal window immediately lists the files and shows individual copy, decoding, and waveform progress. Import runs in the background and can be cancelled; incomplete copies are removed, and successful files are kept if another file fails. Prepared audio and waveforms are cached before fragments appear on the timeline. Formats supported by AVFoundation are accepted, including WAV, AIFF, MP3, and M4A.
3. Click the ruler to position the playhead while keeping the selected range; double-click to clear the range; drag across the ruler to select a range without moving the playhead. The range is highlighted on both the ruler and fragment area; drag either ruler edge to resize it (horizontal resize cursor on hover). Up/Down arrows zoom in/out using the same limits as the View buttons. Zoom in and Zoom out center the view on the playhead, within the timeline bounds. Space pauses and resumes playback with 10 ms fades, retaining the running audio engine, prepared mix and live effects while the project is unchanged. Command-Left jumps to the beginning and Command-Right to the end of the project audio, bringing the destination into view. Left/Right move by 1% of the visible fragment width in both seconds and Tempo modes, keeping active playback running. Shift-Left/Right start shuttle immediately at the current position, without a seek jump or hold delay. From pause, speed rises smoothly from zero. During playback, Shift-Right accelerates the existing stream; Shift-Left slows it from normal playback to zero in 0.25 seconds and then reverses, like analog tape. Both directions are limited to 8× and preserve the same running audio engine during the transition. The Transport menu's Seek Backward/Forward commands retain their 1% viewport step. Releasing the arrow or Shift smoothly returns to 1× over 0.25 seconds if playback was active: reverse motion brakes through zero before turning forward, while forward motion slows to normal speed. From pause, release decelerates to silence over 0.25 seconds and leaves the cursor at the final audible position. The same engine/node stays running through these transitions; effects are restored in the background with a short source crossfade. Ordinary playback also keeps the playhead centered within the timeline bounds. Enter restarts playback from the last start position, marked by an orange vertical notch on the ruler (zero before the first start), using the live crossfade during playback or the prepared transport from pause. Natural playback completion returns the playhead to the last-start notch after effect tails finish. Manual stopping freezes the playhead at the current audio position; the next Play continues from that cursor. Clicking the ruler, a fragment, or empty timeline space selects a new start position; during playback, audio immediately continues from that position without requiring Play again. Each Play uses that one visible position. Resuming a prepared transport flushes obsolete queued audio, including after moving the paused cursor; project edits discard the prepared transport.
4. Drag fragments along the timeline or onto another track. Shift-click to select multiple fragments. Drag on empty fragment-area space to select intersecting fragments with a rectangle; hold Shift to add to the selection. The rectangle updates while dragging without seeking, including during playback; Escape restores the previous selection. Delete removes the selected fragments.
5. When dragging a fragment to another track, its edges snap to other fragment boundaries or its original time within 1% of the visible time span. A vertical dashed guide marks the match across the tracks. Drag either edge of a fragment to adjust its length without changing the source file. The opposite edge stays fixed; resizing is limited to the original recording and a minimum of 10 ms. Escape cancels the live preview; Undo restores the previous length. Split / S splits selected fragments at the playhead. Trim keeps only the range selected on the ruler. Join / ⌘J combines selected fragments on one track into a new WAV, preserving silent gaps and overlap priority.
6. Add a track with + / ⌘T. Tracks support at most two nested levels below a root (root → child → grandchild), including when moving a whole subtree. The nested-track button creates a child track; dragging one track header onto another previews nesting immediately, together with its children and waveforms. Drag near the top or bottom edge of a row to reorder before or after it; drag into its middle to nest. Empty space below the rows moves a track to the root at the bottom. Mouse-up commits the preview with one Undo entry; Escape cancels. Use the context menu or Track → Move Track to Root to return it to the top level. Click a track name once to edit it inline; Enter saves, Escape cancels, and leaving the field saves a nonempty name. The project name in the titlebar edits the same way. Project and track names allow up to 100 characters, counting composed Unicode characters such as emoji as one. Overflowing editor text scrolls horizontally to keep the insertion point visible. Dragging the header, including the name itself, nests the track.
7. Muting a parent track also mutes its children. Deleting a parent removes its subtree after confirmation. All track and fragment changes support Undo / Redo.
8. Save / ⌘S creates a `.sounder` project file and a sibling `media` folder. Newly recorded takes move there after a successful Save; imported audio is copied and originals are preserved. Joined audio and previously saved media are copied as needed. Project paths are relative: move the file and its `media` folder together. Repeated saves add new sources without duplicating existing ones; Save As copies referenced media to the new location. Project packages are not supported. Export / ⌘E opens export options for MP3 (default), WAV or OGG/Vorbis. On first use, rate and bit depth come from the project; only choices used for a successful file export become the next dialog defaults and are stored in the project when saved. Cancelling either dialog or failing to export leaves the previous defaults intact. Projects from earlier builds with unconfirmed dialog choices start from the project audio format. Export conversion does not change the project audio settings.

## CPU and buffer status

The toolbar's CPU indicator measures Sounder's process CPU time (100% = one logical CPU). BUFFER shows completed source/track/effect preparation while starting, then the ready audio queue ahead of playback. Source assembly occupies 0–40%; effect history and initial DSP buffers occupy 40–95%. While idle with no preparation, playback or recording, BUFFER shows the configured queue duration in milliseconds. Click it to edit any integer from 96 to 32768 samples without rounding; the dialog updates milliseconds as you type. The initial default is 1024 samples. A successful project Save remembers its buffer size for new projects, while opening an existing project restores its own recorded size. This is the render-ahead queue, separate from audio-device latency. During preparation and transport it shows measured percentages; a fully ready queue requires a warmed transport, not just retained PCM. Unchanged plug-in editor polls preserve that ready transport and never wait for a busy DSP mutex. Preparation runs on a cancellable worker and reports actual PCM work; very fast preparation may complete between display updates. After Stop, previously calculated PCM remains cached. Moving the playhead adds missing work without clearing that cache. While stopped, Sounder proactively prepares the latest position after moves and edits, keeping the editor available; Play reuses the ready transport or continues an existing calculation. Only project edits invalidate outdated audio. CPU is sampled at 4 Hz and buffer snapshots at 20 Hz without dispatching synchronous work to the audio renderer.

## Audio input and output

Click **In | Out** immediately before Export. The Default row selects the project input and the mixed output independently. Each device offers automatic routing, individual physical channels and stereo pairs. Tracks reuse the same input picker and inherit **Default input** unless overridden. Device UIDs and channel selections are saved in the project and support Undo. Disconnected selections remain visible; starting with an unavailable selected device reports an error instead of switching to another microphone. Routing controls are disabled during playback, recording and other busy operations. Mono inputs save true mono takes, including loop recordings, even in Stereo projects. Mono is expanded only during mixing. Capture retains the project sample rate and bit depth with maximum-quality Mastering resampling; hardware output routing does not change exported files.

## Audio model

New projects default to 48 kHz, Stereo, 24 bit. Click the format label to choose a sample rate of 44.1 / 48 / 88.2 / 96 / 192 kHz, Mono / Stereo, and a bit depth of 16 / 24 / 32 bit. Export options include 44.1 / 48 / 88.2 / 96 / 192 kHz and WAV depth of 16 / 24 / 32 bit. MP3 supports 44.1 / 48 kHz, with 128 / 192 / 256 / 320 kbps; OGG uses Vorbis quality 7. The dialog disables PCM bit depth for compressed formats and rejects unsupported MP3 rates. Bit depth applies to new recordings and WAV exports; effects processing and intermediate files remain Float32. Imported audio retains its original channels; conversion takes place during decoding and mixing. Waveforms use peaks from actual PCM samples, with the left channel above the right for stereo fragments; during recording, the waveform is drawn in real time from incoming PCM buffers, before Stop is pressed. When fragments overlap on the same track, only the more recently created fragment plays, even if it contains silence. The earlier fragment remains underneath and plays again outside the overlap. Separate tracks, including nested tracks, are summed; output is clamped to −1…1.

Editing preserves the original files: trimming and splitting store offsets into the source file. Recordings are saved separately in `~/Library/Application Support/Sounder/Recordings`. Saved projects contain their own audio copies. Recording, importing, and mixing are intended for small projects: decoded audio is kept in memory, and export processing is synchronous. This is a simple editor without stereo pan controls or streaming playback for large projects.

Save your project before running `npm start`: at the user's request, this command forcibly terminates existing instances. During normal shutdown, the app offers to save changes.

## VST / VST3 effects (1.1)

Click **FX** in a track header or choose **Track → Track Effects… (⌘F)**. The floating panel shows the selected track's serial effects chain and stays above the editor until closed. The compact FX window includes **Bypass all / Activate all** beside Rescan; the same action is available from the power icon attached to the shared track/MASTER FX control. Project windows minimize and restore together with the editor. Notifications appear only in the main editor.

- Selecting a result in the installed plug-in picker immediately adds that effect; **Browse…** lets you select a `.vst` / `.vst3` manually, with other file types excluded. Adding an effect immediately opens its native editor, falling back to generic parameter controls if it has no native interface. **Rescan** refreshes the list from `/Library/Audio/Plug-Ins` and `~/Library/Audio/Plug-Ins`. Scanning lists bundles without executing their code; a module is loaded when added.
- Search installed effects by any part of their name in the plug-in picker. **VST3 only** is enabled by default; uncheck it to include legacy VST effects. Up/Down selects results, Enter chooses, and Escape closes the picker.
- Each row’s **Open** slider icon opens the plug-in’s native interface, with generic parameter controls as a fallback for effects without their own window. Plug-in windows are nonmodal and have no Apply or Cancel buttons: parameter changes take effect immediately, including during playback. Closing the window keeps the changes in memory; project Save writes them to disk.
- Drag effect rows to change processing order, or use their **Up / Down** arrow icons. Controls stay at the right edge of each row. Each row also has a **Bypass** power icon (green when enabled, gray when bypassed) and a **Remove** trash icon to delete it and close its editor. Changes support Undo / Redo. Changes to the effects chain refresh active playback.
- The chain processes the sum of the track's own fragments and its already processed child tracks. The result then passes through the parent's chain and continues upward. Each parent's effects are applied exactly once. Root tracks are summed only at the master output.
- Plug-in state, order, and bypass settings are saved in `.sounder`. Plug-in binaries are not copied into the project. Moving a project to another Mac requires installing the same plug-ins; Play / Export reports an error if an active effect is missing. You can disable it with Bypass.
- Split / Trim remain nondestructive; Join combines **dry** fragments so that effects are not applied twice. Waveforms display the fragment’s dry output after volume, normalization, pan and fade curves, before track effects. Output channels follow the project format; a centered mono fragment displays one full-height waveform. Peaks are prepared in the background and cached; changing settings or source bounds refreshes them.

**Processing mode:** playback processes audio in blocks of up to 512 frames on a dedicated worker, using the same plug-in instances as the open editors. Eight short buffers are queued for playback, so parameter changes become audible within the queue and device latency. The queue is replenished when each buffer is consumed, independently of device presentation latency; only the final buffer waits for audible completion. Export renders the current in-memory settings offline. Monitoring the microphone through effects is not yet supported. When starting in the middle of a project, processing begins at time zero to preserve compressor and delay history. Reported plug-in latency is compensated for, and effect tails are limited to 10 seconds per effect (legacy VST effects without tail information use 2 seconds). Source audio is decoded into memory before playback. Timeline clicks and ordinary arrow seeks during playback retain the running engine, node and live effect instances: the worker switches directly to the target source position with a 10 ms crossfade and only pre-rolls declared plug-in latency. Existing effect tails continue naturally instead of rebuilding history from project zero. A configurable render-ahead margin (initial default: 1024 samples total) limits response latency; the cursor switches with the audible output. Rapid pending seeks coalesce to the latest destination. Processed cache regions retain their absolute timeline positions, so skipped spans cannot become false silence hits. Shuttle audition uses already processed mix regions from a temporary disk cache, including effects. Outside that cache it renders small dry windows with fragment gain, pan, fades, Mute and Solo, without running plug-ins. A 10 ms transition joins cached and dry regions. Audio edits and plug-in changes invalidate the cache; it is temporary and is not saved in projects. Normal playback continues processing the live graph so effect edits and track routing remain responsive.

**Compatibility:** native Apple Silicon / Universal VST 2.4 and VST3 audio effects with Float32 processing. Plug-ins receive the selected project sample rate. Stereo projects retain separate channels; for mono projects, stereo output is downmixed to mono. Effects with a fixed mono input receive the sum of the stereo channels. Instruments, MIDI, external sidechain inputs, automation, and Intel-only plug-ins are not supported. Tempo-synchronized effects use 120 BPM. The first compatible audio-effect class in a bundle is used, and its ID is saved in the project. Plug-ins run within the app's process.

The `com.apple.security.cs.disable-library-validation` entitlement is enabled to load third-party plug-ins; Hardened Runtime and Developer ID signing remain enabled. VST3 uses the official [Steinberg SDK](https://github.com/steinbergmedia/vst3sdk); the required source subset and MIT license are in `Vendor/VST3`, and the notice is included in the app bundle. VST2 uses a minimal ABI bridge without including the legacy VST2 SDK.

## Project name and format

Click the name in the top bar to rename the project. Click the sample rate/channel/bit-depth label in the titlebar immediately after the project name to open audio settings. These actions are also available in the File menu. The new name is used for the initial save and export; an existing project file is not automatically renamed. The name, sample rate, and channels are saved in the project and support Undo/Redo. Settings are unavailable during playback and recording.

When the sample rate changes, source files retain their original format; decoded audio is resampled through AVAudioConverter using the Mastering algorithm at maximum quality, preserving fragment timing. Switching from Mono to Stereo restores the original stereo image of imported files. Sources recorded in mono are duplicated across both channels. Increasing the sample rate does not add detail to previously recorded audio.

Existing projects retain their Mono/Stereo mode. Projects without a bit-depth setting use the previous 32-bit Float format. 16- and 24-bit WAV files use integer PCM; the selection is saved in the project and displayed in the top bar.

## Notifications

Persistent hints and the status bar have been removed. Messages appear as rectangles in the upper-right corner: successful actions use green with white text, errors use red with white text, and UX hints use yellow with dark text. Track and fragment deletion notifications also use red with white text. Each message has an 80%-opaque background, remains visible for 4 seconds, then fades out over 0.36 seconds independently; new messages are appended below older ones, and remaining messages move smoothly upward when earlier messages disappear. Notifications do not intercept clicks or dragging.

“Drag tracks to nest” appears on the first attempt to drag a track header; “Shift click to multi select” appears on the first fragment selection. These onboarding hints appear once per app session. Opening a project and Undo/Redo do not reset them. Invalid actions in the FRAGMENTS group show a yellow instruction on every attempt when the required selection is missing. Operational errors appear without a blocking window; dialogs that require a choice remain dialogs.

Rules for future development are saved in `AGENTS.md`. `--ui-test --notifications-ui-test --snapshot /tmp/sounder.png` checks actual interactions, card ordering, independent four-second timers, and the upward movement of remaining messages.

## Shared track format and SRC quality

All tracks record and play using the project's shared settings. Track headers have no fragment counts or local mono/stereo/nested labels. When preparing a mix, each source file is decoded and, if necessary, resampled directly to the current project sample rate; Stereo/Mono is adapted to the selected channel count. Processing and summing use Float32; the selected bit depth is applied once to the final WAV for playback or export. Recording uses the project's sample rate, channels, and bit depth from the start.

Conversion uses [AVAudioConverter Mastering](https://developer.apple.com/documentation/avfaudio/avsamplerateconverteralgorithm_mastering) with `AVAudioQuality.max` and normal priming to preserve timing. The cache is rebuilt when the sample rate changes; conversion always starts from the saved sources, avoiding accumulated losses from repeatedly converting already resampled files.

`npm test` checks mixing 44.1 kHz Mono 16-bit, 96 kHz Stereo 24-bit, and 48 kHz Stereo Float32 audio, followed by a project format change. It verifies duration, channel separation, timing alignment, and preservation of source files. Additional spectral checks for 96 → 44.1 kHz require less than 0.05 dB level deviation and 0.002 rad phase deviation for 1/19 kHz tones, plus more than 90 dB alias rejection for a 30 kHz tone.

## Live recording waveform

Microphone capture uses AVAudioEngine. Incoming buffers are copied to a recording queue, converted to the project format through a streaming Mastering converter, and, for ordinary recording, saved to a separate WAV. Separate peaks for each channel are calculated from the same PCM samples in groups of 128 frames; the UI consumes only new peaks approximately 25 times per second. Level meters and artificial waveforms are not used for the live display.

With **Loop** enabled, recording keeps PCM in RAM and overwrites the same period on every pass. A partial final pass replaces only its prefix; the untouched tail of the previous pass remains. The full retained waveform stays visible while the cursor cycles. **Stop** or **Space** writes one final WAV and adds one fragment/take; earlier passes create no audio files. **Enter** discards the in-memory recording and restarts at the original recording position without saving a discarded pass. A selected timeline period also works when the project has no existing music. The first pass starts at the cursor; audio recorded before the loop is preserved in the final fragment. Each replacement pass merges into the retained audio with 10 ms crossfades at its start and at the end of a partial pass. Stopping before wrapping retains the interval actually captured.

The fragment being recorded and its waveform appear in red over earlier fragments; the timeline scrolls when the playhead leaves the visible area. Stop flushes the converter, writes remaining buffers, and closes the WAV before adding the completed fragment. If recording fails, captured audio is retained when the file contains data, and a red notification appears.

To check the app's own permission, launch it with `open -W -n Sounder.app --args --microphone-test`.

`--ui-test --shuttle-ui-test` checks arrow press/hold/release, immediate start without a seek step, continuous braking/reversal in the same audio stream, accelerated forward audio, continuous centering, restored playback state, text editing and cancellation. Audio tests verify reverse stereo samples, acceleration, cached effects versus uncached dry audio, and cache transitions. Transport regression tests render distinct PCM values for every source frame and verify that the sound and cursor stay aligned through repeated stop/continue cycles and backward/forward seeks. `--ui-test --restart-ui-test` checks Return and keypad Enter, the last-start marker, and playback restarts. `--ui-test --mute-ui-test` checks live MUTE controls without restarting playback, plus Undo/Redo. Audio export codecs are built into the application: [LAME](https://lame.sourceforge.io/) for MP3 and [Xiph Ogg/Vorbis](https://xiph.org/downloads/) for OGG. No external encoder installation is needed. `npm run build:app` verifies the vendored source archive checksums, builds a cached static helper via `scripts/build-codecs.mjs`, and signs/copies it to `Sounder.app/Contents/Helpers`. The build requires Apple command-line build tools; codec source archives and licenses are included in `Vendor/AudioCodecs` and `ThirdPartyNotices.txt`. `--self-test` covers encoding, decoded rate/channels/duration, non-destructive export failure, backward-compatible project loading and saved export choices. `--ui-test --export-ui-test --snapshot /tmp/sounder.png` checks and captures the export dialog.

Click Tempo beside the time display to switch between seconds and a 4/4 bar/beat ruler. In Tempo mode, click the BPM display to set 20–300 BPM (default 120). Metronome enables beat clicks during playback and recording, with an accented first beat every four beats. Its timing follows absolute audio frames and remains aligned after seeks. Clicks are output monitoring only: they bypass track effects and are absent from recorded WAVs and exports. Tempo, ruler mode and metronome state are saved with the project. `--self-test` checks real rendered beat timing at 44.1/48 kHz, accents, seeking, disabling clicks, capture/export separation and project compatibility; `--ui-test --tempo-ui-test --snapshot /tmp/tempo.png` checks the controls and minimum window layout.

The track names and controls stay pinned to the left during horizontal scrolling and follow their rows vertically. The time/tempo ruler stays pinned above the tracks while scrolling vertically. Horizontal scrolling keeps its labels aligned with the fragments; seeking and range selection/resizing remain available on the pinned ruler. `--ui-test --pinned-ruler-ui-test` verifies scrolling, ruler interactions, covered track controls and tempo labels.

When importing multiple audio files, **Separate tracks** is the first and default option. Choose **One track** to place them sequentially or **Separate tracks** to place them at the same cursor time. Separate-track import uses the active track and the following visible tracks, including nested tracks, then creates any missing tracks with the imported fragment names. Single-file import skips this choice. The whole batch, including new tracks, can be undone together.

A single click selects only the clicked fragment, even when it belongs to a group; Shift-click toggles group membership. Dragging any selected fragment moves the entire selection while preserving time spacing. Moving across tracks also preserves relative track-row spacing; the group stops together at timeline zero or the first/last track. Alignment snapping applies to the whole group, and one Undo restores all moved fragments.

Right-click a fragment for **Move up**, **Move down**, and **Delete**. Right-clicking a selected fragment preserves the group and applies actions to all selected fragments, across tracks, as one Undo step; right-clicking an unselected fragment selects it alone. Move up/down changes its priority by one overlapping layer on the same track, affecting both display and playback; a direction is disabled when no overlapping fragment exists there. Layer changes support Undo/Redo.

Use **⌘A** to select all fragments, **⌘C** to copy the selection, and **⌘V** to paste at the cursor. The earliest fragment aligns with the cursor; time spacing, relative track rows and source bounds are preserved. Paste starts at the active track and creates missing tracks if needed. Hold **⌘** when starting a fragment drag to duplicate the selection while leaving originals in place. Paste and drag duplication each use one Undo step. These shortcuts retain normal text behavior while editing names.

In the Tempo dialog, click **Tap** along with the beat to calculate BPM. The field updates after the second click and follows recent tap intervals; a long pause starts a new measurement. Save applies the value; Cancel leaves project tempo unchanged.

Split uses the physical **S** key without modifiers, including **ы** on a Russian keyboard layout. App letter shortcuts use physical key positions in the editor, while typing in names and dialog/plugin text fields keeps its normal behavior. **⌘S** still saves the project.

Enable the **Loop** repeat icon in **PLAYER** (also available in the Transport menu) to repeat playback. A selected timeline range takes priority; with no range, playback loops from zero to the end of the last fragment. Play always starts at the cursor. Starting before a selected period plays the lead-in and first loops when reaching its right edge. Starting after that period continues to the project end without jumping backward. Change the selected range or toggle Loop during playback without restarting audio. The cursor follows the audible loop, Space pauses/resumes and Stop keeps its usual behavior. Loop mode is saved with the project. Recording also follows Loop; tape shuttle temporarily bypasses it, and exports always render once.

The **Stop** icon (or Escape outside a drag/selection gesture) stops audio and returns the cursor to the last playback-start notch, bringing it into view. Before the first playback start it returns to zero; stopping a recording returns to the recording start. Play/Pause and Space still pause at the current position.

In **Import multiple files**, **Tab**, **Shift-Tab**, **↑** and **↓** switch between Separate tracks and One track. Enter confirms the import; Escape cancels.

In **Export audio**, click **Metadata** at the left of the footer to reveal fields for track name, artist, album, album artist, composer, genre, year, track and disc numbers, copyright and comment. Tags are embedded in WAV, MP3 and OGG files, including Unicode text. A successful export remembers the metadata in the project; Save preserves it on disk for the next session. Cancel leaves existing project metadata unchanged.

If a time range is selected on the timeline, **Export audio** shows a **Selected range** checkbox at the bottom. Enable it to export just that interval in WAV, MP3 or OGG; leave it unchecked to export the whole project. Selected empty space is exported as silence, and effects retain the history preceding the selected start.

Numeric fields reject letters and invalid pasted values as you type. Volume, Pan and Normalize accept a leading sign; decimals accept a dot or comma. Fade durations and BPM accept nonnegative values. Metadata year accepts digits, and track/disc numbers also accept the `3/12` form. Existing limits are checked when saving the dialog.

Select fragments and press **N** (physical key, also Russian **т**) or choose **Normalize…** from FRAGMENTS, the Fragments system menu or the fragment context menu. Enter the desired maximum peak level in dBFS (for example -1, -2 or -3) and click **Process**. Each fragment is normalized independently, with linked stereo gain, without changing original files. The waveform, playback and export reflect the gain. Undo/Redo is supported, and the last processed level and fragment gain are saved with the project.

Use **Mute / Unmute** in FRAGMENTS, the Fragments system menu or a fragment's context menu to toggle the selected fragments across tracks. Muted fragments are dimmed and excluded from playback and export; underlying unmuted fragments remain audible. A mixed selection is muted together; an entirely muted selection is unmuted together. The state supports Undo/Redo and is saved with the project and copied fragments. Track mute is independent.

Fragments use automatic **10 ms fade-in and fade-out** to prevent clicks. Overlapping edges crossfade into the underlying audio; newer fragments retain priority outside those short ramps. Very short fragments shorten the ramps to half their duration. Playback and export share the same processing, including range exports and seeking. Join retains the baked fades without doubling them, and changed edges receive fresh automatic fades.

Double-click a fragment or choose **Edit…** from its context menu to adjust volume, pan, fade-in and fade-out. Volume ranges from -48 to +24 dB and is capped at the measured 0 dBFS peak ceiling. Pan ranges from -90° (left) to +90° (right). Each fade has a time in milliseconds and a Linear, S-curve, Exponential or Logarithmic curve; zero disables that fade. Save applies all settings in one Undo step; Cancel leaves the fragment unchanged. Settings persist in projects and copies and affect waveforms, playback and export.

In **Tempo** mode, clicking the ruler, a fragment or empty fragment space places the playhead at the nearest beat start. Selecting a period on the ruler and resizing its handles also snap to beat boundaries without moving the playhead. Hold **Shift** to choose arbitrary positions or range boundaries. Dragging fragments moves them in one-beat steps (a quarter of a 4/4 bar) from their original time, preserving group spacing. Resizing either edge aligns it to a beat boundary within the available source and minimum fragment length. Hold **Shift** for normal free movement/resizing; pressing or releasing Shift during a drag switches the live preview immediately. Shift-click still toggles selection, while Shift-drag keeps the group together.

SOLO beside each track’s MUTE button can be enabled for multiple tracks. Only soloed tracks play; a soloed parent includes its children, and a soloed child retains its ancestors’ effects. MUTE takes priority. Solo works during playback, affects export, supports Undo/Redo and is saved in the project.

Each track has a horizontal **volume** slider in the middle of the header, above the bottom MUTE/SOLO/FX row and a full-height vertical **Pan** slider at the right of its header. Pan up selects the left channel and down selects the right, matching L above R in stereo waveforms and meters. Clicking either rail moves its thumb smoothly to the chosen position; dragging a thumb follows the pointer directly. Double-click either slider to reset volume to 0 dB or Pan to center. The current value appears immediately beside the thumb on hover, at exactly the same position used throughout dragging. It disappears when leaving the control, remaining visible during a drag until release outside the control. Volume ranges from silence to +12 dB (default 0 dB); Pan ranges from left to right (default center), with no effect in mono projects. Adjustments work during playback and recording with a short smoothing ramp. Track mix is applied after its effects and includes child tracks before passing into parent effects. Export uses the same settings; Save preserves them, and one drag is one Undo step. The original audio and recorded files remain unchanged.

Volume slider rails show stereo level meters: L fills the upper half and R fills the lower half independently, in turquoise during playback and red on the actively recording track. Meter widths follow the same -60 to +12 dB scale and thumb travel as the volume control, including track Volume/Pan; a 0 dB signal before these controls reaches the thumb with Pan centered. Silence and Stop leave a neutral rail, and the track header background stays unchanged. Each channel has its own top-right numeric peak readout and one-second maximum hold; mono project output appears equally in both displays. Only the numeric readouts change color: turquoise below -6 dB, yellow from -6 dB, red from -1 dB. It holds maxima for one second. Playback meters follow track output after effects and routing; the metronome is excluded. While recording, the red rail follows the captured input after track Volume/Pan; silence has no fill. Numeric L/R peaks sit just after the volume rail and include the same Volume/Pan gains during playback and recording. Recording peak numbers use the same turquoise/yellow/red thresholds as playback; changing the controls immediately updates capture readouts without changing the recorded source file.

Selected fragments display fade curves at their actual timeline width. Hover over the current upper curve endpoints for compact rising/falling fade cursors; there are no permanent markers. Drag the fade-in endpoint right to lengthen fade-in, or the fade-out endpoint left to lengthen fade-out. The waveform previews the change; releasing commits one Undo step, and Escape cancels. Right-click either curve area for icon-only curve choices, without text labels or checkmarks. These edits affect only the grabbed fragment edge and retain group selection.

In **Save changes to this project?** and **Delete track?**, use **↑/↓**, **Tab** or **Shift-Tab** to choose an action, then **Enter** to confirm. **Escape** cancels; mouse clicks continue to work.

The centered titlebar **master volume** uses the same stereo meter and slider as track volume, with immediate hover values, smooth rail clicks and double-click reset to 0 dB. The titlebar group reads **MASTER → FX → volume**; its **FX** button is the same reusable component as track FX, sharing size, font, hover/active appearance and interaction handling and opens the shared effects window for the entire project. Track buses are summed first, then master effects run in order, followed by master volume. Live changes retain the running transport; master settings and plug-in state are saved with the project and included in exports. Source files, fragment waveforms, microphone recordings and the monitoring metronome remain independent of master processing.

Transport graphics use a display-synchronized playhead at up to 60 FPS, independent of 25 Hz audio-meter and recording-waveform updates. Fragment graphics reuse visible 512-point raster tiles with a 64 MiB cache cost budget; edits and zoom invalidate affected graphics. The pinned track sidebar and ruler use separate surfaces, and display callbacks pause when transport stops or the window is hidden. Audio timing remains driven by the playback clock.

To compare direct and cached fragment rendering and verify transport updates, run the built application with `--ui-test --graphics-ui-test`. Its benchmark measures rendering time for the same viewport, rather than total application CPU usage.

Track and MASTER stereo meters resize separate Core Animation fill layers behind the native volume slider. Incoming signal levels do not redraw the static native thumb. `--ui-test --graphics-ui-test` verifies this isolation and fader redraws. For real-device process CPU measurements, run `Sounder --playback-cpu-ui-test /path/audio.mp3` with an audio file longer than 36 seconds. This diagnostic compares visible playback, minimized playback and Stop in twelve-second stages, then quits. It opens its window above other windows for visibility. A valid visible measurement requires advancing display-frame counts and a visible occlusion state in the log; screen sleep or a locked session can invalidate that stage. Do not compare it to rendering-only benchmarks.

The playhead moves only Core Animation layers inside a stationary, layer-only AppKit surface. It does not move a native view at display cadence or allocate a document-sized bitmap. This avoids repeated tracking-region and accessibility cursor rebuilding; the audible clock and 60 FPS target remain unchanged. `--ui-test --meter-layers-ui-test` checks meter pixels, native thumb redraw isolation and stationary playhead geometry without requiring an active display.

The display link alone presents the moving cursor and viewport; meter polling does not perform a second scroll pass between display frames. The numeric time/BPM readout refreshes at up to 25 Hz, while playhead motion and horizontal following remain at up to 60 FPS. Toolbar buttons also avoid re-installing an already active cursor.

Timeline seeking during playback and starting/resuming Play ease horizontal centering over one second. Audio and the playhead immediately follow the selected position; only the viewport scroll is eased toward the moving playback cursor. Repeated seeks restart from the current viewport, and pausing freezes an unfinished transition. While stopped, Left/Right move the marker immediately and center the viewport smoothly over one second, without starting audio; held repeats update the animation target without postponing its completion. Display callbacks stop after idle centering finishes. Explicit zoom, boundary commands and arrow seeking during playback retain immediate centering.

Track volume is vertically centered with the neutral Pan position; MUTE/SOLO/FX sit below with a small bottom inset. Track and MASTER volume share the same longer rail, narrow transverse thumb and compact peak labels, with the channel suffix after the level (`-3.0 dB L`, `-4.2 dB R`).

Track and MASTER peak readouts hold maxima for one second, then follow current levels. Silent channels have no numeric label. Stopping clears the rails immediately. Each channel’s numbers fade out over one second when its signal disappears or playback ends.

The titlebar groups Open, Save and Show project in Finder with the same icon spacing as the editor toolbar. Show project in Finder reveals the saved project alongside its media folder; it is disabled until the project is saved.
